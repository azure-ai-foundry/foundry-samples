# ABO RL headroom data preparation

This sample builds the two difficulty-controlled datasets used in [When Does RL Actually Help Fine-Tuning?](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/when-does-rl-actually-help-fine-tuning-a-difficulty-controlled-study-on-structur/4535077). It uses the public Amazon Berkeley Objects (ABO) listings metadata and has no runtime dependency outside the Python standard library.

The generated arms contain the same products and split membership:

- **Easy:** structured `productType`, `color`, `material`, and keyword lines are visible in the prompt.
- **Hard:** those lines are hidden, so attributes must be inferred from the product name and bullet text. The free-text targets are also rephrased from structured attributes.

The script creates data only. Re-running SFT and GRPO requires access to the Microsoft Foundry Interactive Post-Training API (Project Loom), which is currently in private preview.

## Prerequisites

- Python 3.10 or later
- About 100 MB of free space for the compressed ABO listings metadata, plus space for generated JSONL files
- AWS CLI only if you use the download command below; no AWS account or credentials are required

No `pip install` step is required.

## Files

| File | Purpose |
| --- | --- |
| `abo_prep.py` | Downloads nothing; reads ABO JSON/JSONL files, derives silver-label targets, and writes deterministic splits |
| `README.md` | Data preparation, validation, training handoff, and experiment settings |
| `requirements.txt` | Empty by design; the script is standard-library only |
| `sample.yaml` | Validation pipeline metadata |

## Run the offline self-test

The self-test uses bundled synthetic records and does not access the network:

```bash
python abo_prep.py --selftest
```

A passing result ends with `SELFTEST PASS`. It verifies both output schemas, paired product IDs, and that hard prompts do not expose the hidden structured labels.

## Download ABO listings metadata

From the sample directory:

```bash
aws s3 cp --no-sign-request --recursive \
  s3://amazon-berkeley-objects/listings/ data/abo-listings/listings/
```

This experiment uses only the listings text metadata, not the image or 3D assets. ABO is licensed under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); preserve the attribution when redistributing derived data.

## Build both experiment arms

Run one command so that the easy and hard arms are selected, shuffled, and split together:

```bash
python abo_prep.py \
  --abo-glob "data/abo-listings/listings/metadata/listings_*.json.gz" \
  --out-dir data/processed \
  --category fashion \
  --difficulty both \
  --max 6000 \
  --seed 42
```

Expected summary:

```text
data/processed/easy: train 4800 / val 600 / test 600
data/processed/hard: train 4800 / val 600 / test 600
scanned ... ABO records -> 6000 aligned easy/hard pairs
```

The output layout is:

```text
data/processed/
|-- easy/
|   |-- all.jsonl
|   |-- train.jsonl
|   |-- val.jsonl
|   `-- test.jsonl
`-- hard/
    |-- all.jsonl
    |-- train.jsonl
    |-- val.jsonl
    `-- test.jsonl
```

Each row contains:

```json
{
  "product_id": "...",
  "student_prompt": "...",
  "completion": "{...8-field JSON string...}",
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ]
}
```

The labels are deterministic silver labels derived from ABO attributes. They are not human annotations and are not generated by an LLM.

## Reproduce the training comparison

After your Project Loom access is approved, follow the private-preview onboarding material to install the Loom cookbook, configure its Python environment, and authenticate to the assigned Foundry project. Use the generated `train.jsonl`, `val.jsonl`, and `test.jsonl` paths for one arm at a time.

Keep every training setting fixed across arms:

| Setting | SFT | GRPO |
| --- | --- | --- |
| Base model | Qwen3-32B | Easy or hard SFT checkpoint |
| Adapter | LoRA rank 32 | LoRA rank 32 |
| Learning rate | `5e-4` | `2e-5` |
| Batch or groups | batch 32 | `group_size=8`, `groups_per_batch=8` |
| Objective | Cross-entropy | Importance sampling |
| Budget | 1 epoch, 4,800 rows | 64 steps |
| Sampling | n/a | temperature 1.0 |
| Seed | 42 | 42 |

For GRPO, apply the same reward shaping to both arms:

- Anneal the Semantic-IoU threshold from 0.5 to 0.7 over approximately 70% of training.
- Use field weights `overall_vibe=3`, `trend_signals=3`, `vibe=2`, and `quick_semantic=1.5`.
- Start GRPO from the corresponding arm's SFT checkpoint.

Do not compare a fully trained arm with an under-trained arm. Confirm that each SFT validation curve has plateaued before starting GRPO.

## Reproduce the 48-item evaluation

The blog reports one fixed subset from each 600-row test split. The evaluation loader:

1. Loads `test.jsonl`.
2. Shuffles it with seed 42.
3. Selects the first 48 shuffled rows.

Use that same subset for all four checkpoints: easy SFT, easy GRPO, hard SFT, and hard GRPO.

Score the four free-text fields with cosine similarity and the four inference fields with Semantic-IoU at threshold 0.7, using `text-embedding-3-small`. Evaluation uses equal field weights and a fixed denominator of eight; malformed JSON or a missing field contributes zero. See the blog appendix for the exact metric definitions.

Expected weighted scores are approximately:

| Arm | SFT | GRPO | Absolute gain |
| --- | ---: | ---: | ---: |
| Easy | 0.8885 | 0.8996 | +0.0111 |
| Hard | 0.6983 | 0.7498 | +0.0515 |

These are single-seed results on 48 items, not significance estimates. Small rerun differences are expected.

## Troubleshooting

- **No files matched:** verify the quoted `--abo-glob` path and confirm `listings_*.json.gz` exists under `listings/metadata/`.
- **Fewer than 6,000 rows:** use the complete listings metadata download and keep `--category fashion`.
- **Arms have different IDs:** regenerate them together with `--difficulty both`; do not build them from independently filtered source snapshots.
- **Training command is unavailable:** Project Loom access and its cookbook onboarding are separate from this public data-preparation sample. Complete the intake form and wait for approval.
